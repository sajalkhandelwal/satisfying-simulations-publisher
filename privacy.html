This page describes how Satisfying Simulations Local Publisher currently accesses, uses and stores data while helping its owner review and publish original videos.

Google access and its purpose

  • Channel identity: the app requests the authorized account's YouTube channel ID and verifies it against the exact channel selected by the owner. A different channel is refused.
  • Publishing: the current connection requests youtube.force-ssl. This is a broad YouTube management permission. The app uses it to verify the channel, upload an approved master with its approved title, description and tags, inspect processing and delivery, and update visibility according to the approved settings. The current local review workflow requires owner approval before upload or status update.
  • Known-video statistics: the app can read available Data API statistics, such as views, likes and comment counts, for its known delivered videos. Missing statistics remain unknown.
  • Optional Analytics: if explicitly requested and enabled, yt-analytics.readonly supports reports such as views, estimated watch time, average view duration, shares and subscribers gained. This optional report access is separate from the base connection.
  • Authorization credentials: Google issues access and refresh tokens so the app can make authorized requests. The app does not ask for or store the owner's Google password.

What stays on the owner's computer

The local SQLite database and artifact folders retain job IDs, channel configuration, titles, descriptions, tags, approval records, exact-master hashes, upload-session information, delivered video IDs, processing or publication status, errors and any collected metrics. Local media files, manifests and generated metadata are also retained for review and recovery.

OAuth client information and refresh tokens are stored in a private, Git-ignored local environment file. The connection helper checks owner-only file permissions (mode 0600) and writes changes atomically. Credentials are plain text at the application-file level; the app does not implement a separate credential vault. Operating-system volume encryption is a separate device control. Access tokens are refreshed through Google and cached in process memory while needed.

Local AI and data sharing

The current setup sends content briefs, actual simulation outcomes, draft metadata and any included owned-account performance context to a local Ollama model on the same computer for inference. It stores model requests and results locally for diagnosis and review. No hosted AI provider or hosted fallback is configured in this setup, and the app has no model-training workflow.

Google receives authorization requests, approved upload bytes and metadata, and the API queries needed for channel verification, delivery checks and enabled statistics. Content becomes visible on YouTube according to the approved visibility setting. The current configuration does not send Google data to an advertising service or sell it. Local helpers and people with access to the owner's machine may be able to access local records; machine access and backups must be managed by the owner.

Retention and deletion

The current implementation has no automatic expiry period for local jobs, media, metrics, logs or backups. The owner controls how long these records are kept. To stop use, stop the local publisher and revoke Google access; then arrange local removal of credentials and the relevant database, artifacts, logs and backup copies. Local deletion is a manual owner-controlled operation, not a self-service deletion feature on this website.

For help identifying or removing local app records, contact aicontentfactoryiiit@gmail.com. Removing local records does not itself delete a video already uploaded to YouTube. Manage those videos separately in YouTube Studio. Revoking access does not automatically erase information already stored locally.

Revoke Google access

Open your Google Account connections, select this app, review its access, and choose the available removal action. Revocation stops further authorized access unless the owner grants access again. Google's connection-management instructions explain the available controls.

Website hosting

The selected static website host is GitHub Pages. These pages use local CSS and contain no analytics scripts, remote fonts, embedded media, forms or sign-in controls. GitHub may process website-request information, such as IP addresses and request details, under its GitHub General Privacy Statement. Hosting-related processing is separate from the publisher records held on the owner's computer.

Changes and contact

This disclosure must be reviewed when actual permissions, storage, providers or data uses change. App support and privacy contact: aicontentfactoryiiit@gmail.com.
